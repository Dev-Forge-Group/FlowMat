# 주간 사용량

> **현행 문서** · 확인 2026-11-22(`main` V140). 질의나 기준을 바꾸면 같은 변경에서 고친다.

[로드맵](../status/ROADMAP-2026-11-23.md) §6 4번에 따라 파일럿이 무엇을 얼마나 쓰는지 개인정보 없이 잰다. 이 수치로 §7 판정 1의 "매주 쓴다"를 센다. 새 추적 코드는 넣지 않았다. 이미 DB에 있는 기록만 읽는다.

```bash
docker exec -i <DB 컨테이너> psql -U <사용자> -d <DB> -v weeks=8 -f - < scripts/ops/usage-weekly.sql
```

`weeks`의 기본값은 8주다. 질의는 자료를 읽기만 한다. 임시 뷰 하나를 만들지만 연결이 끝나면 사라진다. 그 때문에 읽기 전용 복제본(hot standby)에서는 돌지 않으니 원본 DB에서 돌린다.

## 1. 무엇을 세는가

결과는 프로젝트 ID마다, ISO 주마다 한 줄이다. 사용자, 이름, 수량, 금액은 나오지 않는다. 그래서 보고를 남겨 두거나 공유해도 된다. 어느 ID가 어느 공장인지는 운영하는 사람만 안다.

| 칸 | 세는 것 | 나누기 |
|---|---|---|
| items | 품목을 만든 수 | 준비 |
| steps | 공정 노드를 만든 수 | 준비 |
| published | 흐름 개정을 게시한 수 | 사용 |
| plans_confirmed | 계획을 확정한 수(ADR-043) | 사용 |
| work_orders | 작업지시를 만든 수 | 사용 |
| production_runs | 생산 실행을 만든 수 | 사용 |
| flow_runs | 흐름 실행을 시작한 수 | 사용 |
| ledger_lines | 재고 원장에 줄을 쓴 수(입고·이동·생산·예약 등) | 사용 |
| purchase_orders | 구매 주문을 만든 수 | 사용 |

**`used`(그 주에 썼다):** 그 주에 "사용" 칸의 일이 하나라도 있고, 그 일이 프로젝트를 만든 지 하루가 지난 뒤에 있었다는 뜻이다.
- 하루를 두는 까닭은 견본이다. 홈의 "견본으로 시작"은 몇 초 만에 게시와 재고 입력까지 하므로, 이 조건이 없으면 견본 프로젝트도 썼다고 세게 된다.
- 품목·공정 입력만 한 주는 준비로 보고 세지 않는다.

마지막 표는 최근 4주(이번 주 포함) 모두 `used`인 프로젝트를 보여 준다. 판정 1은 파일럿 3곳 중 2곳 이상이 이 표에 있는지를 본다.

## 2. 세지 못하는 것

- **계획 미리보기.** `plan-previews`는 저장하지 않으므로 몇 번 불렀는지 남지 않는다. 확정까지 간 것만 `plans_confirmed`에 잡힌다. 미리보기를 세려면 개인정보 없는 카운터가 따로 필요하다. 파일럿 첫 주에 확정 수가 너무 적으면 그때 넣는다.
- **읽기만 한 것.** 화면을 열어 보기만 한 것은 남지 않는다.
- **지운 것.** 지운 품목이나 노드는 세지 않는다.

## 3. 돌리는 때

파일럿 동안 매주 월요일에 지난 8주를 뽑아 둔다. 판정 1(2027-02-19) 전에는 그 결과로 4주 연속 쓴 곳을 센다. 매일 백업([backup-restore](backup-restore.md) §7)이 같은 DB를 읽으니, 백업 시각과 겹치지 않게 돌린다.
