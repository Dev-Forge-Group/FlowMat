# 파일럿 배포안 비교

> **제안 문서** · 2026-11-24. 승인 전이다. 계정 개설, 비용 발생, 외부 서비스 신청은 하지 않았다.

사용자 결정(2026-11-24)은 두 가지다.

- 파일럿은 비용 최소화가 원칙이다.
- 실제 비용 발생과 외부 서비스 개설은 승인 뒤에 한다.

여기서는 공장 3곳의 파일럿(로드맵 §6의 3번)을 기준으로 비교한다.

**가격은 추정이다.** 이 환경은 가격 페이지에 닿지 못해서, 2026년 중반까지의 공개 가격으로 셌다. 승인할 때 각 서비스의 가격 페이지에서 다시 확인한다.

## 1. 필요한 것

| 구성 | 지금 | 비고 |
|---|---|---|
| 앱 | Spring Boot jar(Java 21) | 메모리 1–1.5 GB. `prod` 프로필은 약한 비밀값과 localhost 주소로는 기동하지 않는다 |
| DB | PostgreSQL 16 | Flyway가 기동할 때 마이그레이션한다. 운영 적용은 [§5 절차](backup-restore.md) |
| Redis | 7 | 갱신 토큰, 로그인 실패 수, 시간당 한도 |
| 화면 | Vite 빌드 정적 파일 | 앱 앞의 웹 서버가 제공한다 |
| TLS·도메인 | 없음 | 도메인 하나(연 1–2만 원), Let's Encrypt |
| 메일 | SMTP 설정(`MAIL_HOST`) | 가입 인증 코드에 필요하다. 발송 서비스가 필요하다 |
| 백업 | [매일 백업](backup-restore.md) §7(14벌, 복원 확인 포함) | 기계 밖의 저장소가 필요하다 |

## 3. 권장: A (국내 리전 VM 1대)

이유:

1. 국내 안 중 가장 싸다.
2. 개발·CI와 같은 Compose 구성이라, 이미 검증한 것들이 그대로 돈다. 업그레이드·복원 리허설, 매일 백업, 실 API 여정 테스트다.
3. 국외 이전 고지 없이 처리방침을 쓸 수 있다.

배포 전에 할 일은 모두 클라우드 세션에서 할 수 있다. 계정과 결제만 사람이 한다.

1. **설정 파일:** Compose 운영 파일과 Caddy 설정(TLS)을 만든다. 비밀값은 서버의 env 파일(권한 600)에만 둔다. **들어감(2026-11-28):** [`deploy/pilot/`](../../deploy/pilot)과 [배포 절차](pilot-deployment.md). 버리는 컨테이너에서 리허설했다.
2. **백업:** 매일 백업을 기계 밖 저장소(객체 저장소)로 복사한다. 올리기 전에 암호화한다. 한 달에 한 번 복원 리허설을 한다.
3. **로그인 보안:** [로그인 보안](login-security.md) §4를 그 배포에서 확인한다.
4. **처음 띄우기:** 빈 DB에 후보 jar를 띄운다. 데모 자료가 운영 DB에 들어가지 않는지 확인한다(`ProdMigrationIsolationTest`와 같은 내용).
5. **다음 단계로 넘어갈 때:** 유료 고객이 3곳을 넘거나, 가용성 약속(SLA)이 생기거나, 잃어도 되는 자료가 24시간보다 짧아져야 하면 DB를 관리형으로 떼어 C로 간다.
