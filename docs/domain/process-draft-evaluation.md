# 설명으로 시작: 평가 설계

> **현행 문서** · 2026-11-24. [ADR-047](../architecture/adr/ADR-047-process-draft-from-a-description.md)을 켜기 전에 할 평가다.

사용자 결정(2026-11-24)은 다음과 같다.

- 운영에서 기본으로 켜는 것은 보류한다.
- AI는 고를 수 있는 기능이다. 핵심 제품은 AI 없이도 끝까지 된다.
- 평가 설계, 계약, 비용 상한, 실패 때의 동작은 미리 준비한다. 외부 API 호출과 과금은 따로 승인받은 뒤에만 한다.

이 문서는 그 준비다. **아직 한 번도 호출하지 않았다.**

## 1. 입력·출력 계약

- **요청:** `POST /process-drafts` `{description}`
  - 로그인해야 한다.
  - 설명은 2,000자까지다.
- **응답:** `ProcessDraftResponse`. 모델에도 같은 모양을 구조화 출력으로 요구한다.
  - `title`
  - `summary`
  - `items[]{code, name, type, unit}`
  - `steps[]{name, inputs[], outputs[], minutes}`
  - `target{item, quantity}`
- **검사:** 서버가 `ProcessDraftCheck`로 검사한다. 크기, 이름, 코드, 종류, 단위, 수량, 단계 순서, 만드는 단계 하나, 목표를 본다. 하나라도 어기면 502다.
- **보내는 것:** 설명만 간다. 프로젝트 자료, 이름, 이메일은 가지 않는다.

## 2. 실패 때의 동작

AI가 없어도 홈의 "견본으로 시작"과 편집기의 직접 그리기는 그대로 된다.

| 상황 | 응답 | 화면 |
|---|---|---|
| 꺼져 있음(기본) | 503 | "이 서버에는 설명으로 시작이 켜져 있지 않습니다. 견본으로 시작해 보세요." |
| 한 사람이 시간당 10번을 넘음 | 429 | 서버 문구 |
| 서버 전체의 하루 상한(기본 30번, `APP_AI_PROCESS_DRAFT_DAILY_LIMIT`)을 넘음 | 429 | "견본으로 시작하거나 내일 다시" |
| 모델 거절, 시간 초과(2분), API 오류 | 502 | 서버 문구 |
| 답이 검사를 통과하지 못함 | 502 | 서버 문구. 아무것도 만들지 않음 |

## 3. 비용 상한

가격은 2026-11의 공개 가격이다(백만 토큰당 입력/출력). 이 환경에서는 가격 페이지를 다시 확인할 수 없어서, 승인할 때 다시 본다.

| 모델 | 입력/출력 | 한 번 최대(입력 2천, 출력 상한 1만6천) | 한 번 보통(출력 4천) |
|---|---|---|---|
| `claude-opus-5-5`(지금 기본) | $4 / $20 | 약 $0.33 | 약 $0.09 |
| `claude-sonnet-5-5` | $2 / $10 | 약 $0.16 | 약 $0.04 |
| `claude-haiku-5-5` | $0.10 / $0.50 | 약 $0.008 | 약 $0.002 |

- **하루 상한:** 서버 전체 30번이다. Opus로 하루 최대 약 $10, 한 달 최대 약 $300이다. 보통으로 쓰면 한 달 약 $80이다.
- **승인할 숫자:** 사람이 정할 것은 상한 값(`APP_AI_PROCESS_DRAFT_DAILY_LIMIT`)과 모델이다.
- **세는 방식:** 검사에 걸린 답도 비용이 들었으므로 상한에 센다.
- **평가 한 번의 비용:** 아래 사례 12개를 모델 셋으로 각 3번 돌리면 최대 약 $18이다.

## 4. 평가 세트와 채점

- **사례:** [`process-draft-evaluation-cases.json`](process-draft-evaluation-cases.json)
  - 지어낸 설명 12개다. 업종은 식음료, 제빵, 조립, 봉제, 화장품, 금속, 도료, 커피, 전자, 사출, 김치, 포장이다.
  - 실제 고객 자료는 넣지 않는다.
  - 파일럿 설명이 모이면 개인정보를 뺀 뒤 더한다.
- **사람 없이 채점하는 것**(같은 답이면 같은 점수):
  1. **검사 통과:** `ProcessDraftCheck`의 문제가 0개다.
  2. **구조:** 단계 수가 사례의 범위 안이다. 재료가 `minMaterials`개 이상이다. 목표 단위가 `targetUnits` 안이다. 중간품 여부가 `semi`와 같다.
  3. **실행 가능:** 초안을 견본 빌더로 버리는 DB에 만든다. 목표 수량으로 `plan-previews`를 부르면 거절 없이 계획이 나온다.
  4. **시간과 토큰:** 응답 시간과 사용 토큰(`usage`)
- **사람이 채점하는 것**(고를 수 있음): 제조를 아는 사람이 그럴듯함을 1–5로 매긴다. 빠진 공정, 엉뚱한 재료를 본다.
- **켜는 기준**(모델마다, 3번 돌린 평균):
  - 검사 통과 90% 이상
  - 구조 80% 이상
  - 실행 가능 80% 이상
  - 응답 시간 중앙값 30초 이하
  - 기준을 채운 모델 중 가장 싼 것을 고른다.
  - 아무 모델도 채우지 못하면 켜지 않는다.

## 5. 승인 뒤의 순서

1. 사람이 모델 후보, 하루 상한, 평가 비용(최대 약 $18)을 승인한다.
2. 키를 클라우드 환경의 비밀값으로 넣는다. 저장소와 로그에는 남기지 않는다.
3. 평가 실행기를 만들어 돌린다. 사례별 점수와 비용을 표로 남긴다. 실행기는 아직 없다. 키 없이 만들 수 있는 부분은 승인 뒤에 함께 만든다.
4. 기준을 채우면, 파일럿 배포에서만 `APP_AI_PROCESS_DRAFT_ENABLED=true`로 켠다. 처리방침의 국외 이전 항목([개인정보](../operations/personal-data.md) P7)을 먼저 채운다.
