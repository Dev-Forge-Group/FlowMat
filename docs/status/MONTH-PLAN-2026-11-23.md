## FlowMat의 본질

**흐름을 설계하고, 설계한 대로 돌려 보고, 실제로 돌린 것을 맞게 남긴다.** 공정과 포트, 연결, 조건으로 흐름을 그린다. 무엇이 어디로 얼마나 가는지, 어디서 막히고 무엇을 잃는지를 실행 전에 본다. 실제 실행은 원장에 맞게 남긴다. 제조(BOM·재고·생산·품질)는 이 흐름 위에 얹힌 첫 업종이다.

이 기준으로 보면 지금 가장 약한 곳은 가운데, **"설계한 대로 돌려 보기"**다.

## 지금 상태 (2026-11-21, `main` `9a71d26`)

- **흐름의 의미는 서버 Java에만 있다.**
  - 31가지 검증 규칙은 `WorkflowValidationService` 654줄이다. 포트 스키마 호환, 게이트웨이·분할·합류, 손실·지연, 고립·순환 등을 본다.
  - 실행 중 경로 계산은 `FlowRunGraph` 400줄이다.
  - 편집기에는 조건식 언어만 Rust→WebAssembly로 들어가 있다(11-20).
- **편집기는 서버를 거쳐야 결과를 본다.**
  - 검증은 저장된 그래프를 서버에 묻는다(`useWorkflowValidationQuery`).
  - 흐름을 돌려 보려면 발행하고 실행을 만들어야 한다. `simulation` 실행 종류는 있다. 하지만 서버의 생산 실행으로만 있고, 그리는 중에 볼 수는 없다.
- **크기.** 백엔드 Java 74K줄이고, 흐름 핵심(workflow·flowrun·rule)은 그중 14K줄이다. 프런트는 56K줄(편집기 사본·테스트 제외)이다. 가장 큰 세 화면이 2,182줄(`WorkflowCanvasPage`), 1,537줄(`CanvasViewport`), 1,475줄(`WorkspaceEditorLayer`)이다.
- **CI**(같은 커밋에서 잼): 백엔드 전체 8.5분(테스트 3,300여 건), 모의 E2E 3조각 7.5분, 실 API E2E 7분, 프런트 1.7분.
- **보안 검사.** OWASP 검사는 10-25부터 매주 실패했다. NVD 키가 빈 값이었기 때문이다. 고치는 PR이 #129다.
- **이번 달에 들어온 것.**
  - Rust 조건식 언어(WASM 205KB).
  - Python CP-SAT 순서 풀이기(합성 사례에서 오늘의 최선보다 30.8% 적음).
  - 연동 작업.
  - 안내 보기.

## 진행 (2026-11-21, PR #130, merge 전)

계획보다 일찍 시작했다. 릴리스 후보 태그(1주차 1번)가 OWASP 결과를 기다리는 동안 브랜치에서 했다. `main`은 태그를 붙일 커밋에 그대로 둔다.

- **1주차 2번 ADR-040: 끝.**
- **1주차 3번 고정 입력: 끝.** `compute/flow-kernel/fixtures/`에 Java가 답을 적는다.
  - `validation.json`: 그래프 170개. 31규칙이 모두 걸린다.
  - `routing.json`: 그래프 130개와 보낸 출력들. 결정 이유 여덟 가지가 모두 나온다.
  - 그래프는 서버 응답 모양이다.
- **1주차 4번 CI 시간: 재 봤고, CI에는 넣지 않음.** 백엔드 테스트를 JVM 여러 개로 나눠 돌리는 `-Ptest.forks=N`을 더했다.
  - 4코어 기계: 1개 438초, 2개 319초(−27%), 3개 339초. 3,356개가 모두 통과했고, 순서에 기대는 테스트는 없었다.
  - CI 실행기: 테스트 단계가 1개 8분 8초, 2개 8분 29초로 줄지 않았다. 그래서 기본값은 1개다.
  - 4코어 이상인 개발 기계에서는 `-Ptest.forks=2`가 빠르다.
  - CI를 줄이려면 다른 길이 필요하다: 테스트를 job 여러 개로 나누거나, 더 큰 실행기를 쓴다. 다음 후보로 적는다.
- **2주차 1번 Rust 검증 31규칙: Rust 쪽 끝.** `cargo test`가 170개 그래프의 답을 메시지·근거·고치는 법·숨기는 경고·순서까지 Java와 같게 낸다.
  - WASM 빌드로 같은 확인(`check-fixtures`)과 크기 재기는 편집기에 붙일 때(2주차 2번) 한다.
- **3주차 1번 Rust 경로 계산: Rust 쪽 끝.** 130개 그래프에서 `FlowRunGraph`와 같은 결정을 낸다. 판 읽기 실패, 단계 실패, 손실, 분할 몫, 합류까지 같다.
- **2주차 2번 편집기의 즉시 검증: 첫 판.**
  - 작업 화면에 "As drawn: N errors, M warnings" 한 줄이 있다. 캔버스가 바뀌면 150ms 뒤 커널로 다시 검사하고, 누르면 이슈 목록이 열린다.
  - 확인한 것:
    - 서버에 묻지 않는다.
    - 연결을 지우면 그 이슈가 사라진다(모의 브라우저 테스트).
    - 저장할 수 있는 고정 입력 그래프는 캔버스 보기 모델을 거쳐서도 서버의 이슈와 같다(단위 테스트).
    - 저장된 같은 흐름에서 "As drawn"의 수와 이슈 목록이 서버의 "Check workflow"와 같다(실 API 브라우저 테스트, `workflow-validation.spec.ts`).
  - 남은 것: 공정·포트·연결 위에 이슈 표시.
- **2주차 3번 조건식 크레이트 흡수: 편집기 쪽 끝.** 커널 모듈이 조건식도 내보내므로 편집기는 모듈 하나(561KB, gzip 168KB)만 싣는다. 조건식 고정 입력 1,641개도 이 모듈로 통과한다. Rust 소스를 한 크레이트로 합치는 것은 아직이다.
- **고정 입력이 찾은 Java 결함 셋.** 고쳤고, 각각 테스트가 있다.
  - 나머지 연결이 둘인 분할이 판에 있으면 경로 계산이 NPE(500)를 냈다. 이제 409로 거절한다.
  - 포트 스키마의 이름 순서가 JVM을 띄울 때마다 달랐다. 그래서 둘 이상 어긋날 때 오류가 가리키는 이름이 서버를 다시 띄울 때마다 바뀔 수 있었다. 이제 이름 순서다.
  - 자원 종류가 비고 옛 `ioType`도 없는 포트를 이으면 계약 검사가 NPE를 냈다.

## 한 달 뒤 목표

1. **흐름 커널 하나.** 흐름의 의미가 한 Rust 크레이트(`compute/flow-kernel`)에 있고, Java와 같은 답을 낸다. 의미란 포트 호환, 조건식, 검증 31규칙, 게이트웨이·분할·합류·손실 경로 계산이다. 같은 답인지는 고정 입력으로 본다.
2. **그리는 즉시 검증.** 편집기가 커널(WASM)로 저장 없이 검증한다. 서버 검증과 같은 이슈 코드가 같은 공정·연결에 나온다.
3. **편집기 안에서 흐름 돌려 보기.** 견본 입력을 넣으면 커널이 경로를 따라간다. 무엇이 어디로 얼마나 가는지, 어디서 막히고 무엇을 잃는지가 캔버스에 보인다. 답은 같은 그래프·같은 입력에서 서버 `FlowRunGraph`와 같다.
4. **서버도 같은 커널을 쓸지 숫자로 정한다.** JVM 안에서 WASM을 돌리는 것(Chicory, 순수 Java WASM 런타임)과 Java 유지를 비교한다. 기준은 같은 답, 검증 한 번의 지연, 메모리다. 기준을 넘으면 Java 중복을 지우고, 못 넘으면 Java를 두고 고정 입력으로 대조한다.
5. **릴리스 후보 `v0.9.0-rc.1`.** 점검표를 같은 커밋에서 다 통과하고 태그가 붙어 있다.

## 원칙

- **본질이 아니면 손대지 않는다.** 원장·트랜잭션·권한·저장은 Java가 잘하므로 둔다. 바꾸는 것은 흐름의 "의미"가 두 곳에 갈라지거나, 설계 중에 보이지 않는 곳이다.
- **같은 답이 먼저다.** 조건식 언어처럼 Java가 고정 입력에 답을 적는다. 새 구현은 그 답을 다 맞춘 뒤에만 쓴다. 의미를 바꾸면 Java의 답을 다시 쓰고 diff를 읽는다.
- **숫자로 정한다.** 커널을 서버에서 쓸지, 화면을 나눌지, CI를 바꿀지는 재고 나서 정하고, 잰 값을 문서에 남긴다.
- **스펙과 빌드는 고쳐도 된다**(사용자 11-21). 고칠 때는 같은 변경에서 문서·테스트·CI를 맞춘다.

## 이번 달에 하지 않는 것

- 제조 모듈(BOM·재고·생산·품질)을 다른 언어로 옮기기. 원장과 트랜잭션은 Java에 둔다.
- DB 바꾸기, 모듈을 다른 저장소로 옮기기.
- 프런트 프레임워크 바꾸기. 커널이 프레임워크 밖(WASM)에 있으므로 React를 바꿀 이유가 되지 않는다.
- 실시간 협업 엔진 교체(다음 달 후보로만 적는다).
- 시간·용량까지 넣은 시뮬레이션(3주차는 양과 경로만이다).

## 위험

- **커널과 Java가 어긋남.** 31규칙의 근거(`evidence`)와 메시지까지 같아야 한다. 고정 입력이 규칙마다 걸리지 않으면 어긋남을 못 잡는다. 1주차 3번에서 규칙마다 걸렸는지를 테스트가 센다.
- **WASM 크기.** 조건식만으로 205KB(gzip 68KB)다. 커널 전체가 1MB를 넘으면 편집기 첫 화면이 느려진다. 처음 그릴 때 늦게 싣고, 크기를 CI에서 잰다.
- **언어가 하나 는다.** Rust는 이미 조건식에서 쓰고, CI(`compute.yml`)와 재현 빌드(`wasm/build.sh --check`)가 있다. 새 도구는 더하지 않는다.
- **Chicory의 속도.** 순수 Java 해석기라 Java 구현보다 느릴 수 있다. 그 경우 4주차 기준에서 Java를 둔다. 그래도 편집기의 즉시 검증과 돌려 보기(목표 2·3)는 그대로 남는다.
