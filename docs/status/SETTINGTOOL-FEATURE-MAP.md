# settingTool(optimized_setup) 기능 대조

> **현행 문서** · 확인 2026-11-14(settingTool `7762b05`, FlowMat `main` V135). 기능을 가져오거나 가져오지 않기로 정하면 같은 변경에서 표를 고친다.

[월간 계획](MONTH-PLAN-2026-11-16.md)의 "optimized_setup 기능 가져오기" 3주차 산출물이다. [Dev-Forge-Group/settingTool](https://github.com/Dev-Forge-Group/settingTool)의 기능을 FlowMat에 대 보고, 가져올 것과 그 순서를 정한다. 문서(`README.md`, `docs/Qt.md`, `docs/SMRT_SPACE.md`, `docs/new_site_setup.md`)와 `Qt/Utils/`의 코드를 읽고 썼다.

## 1. settingTool이 하는 일

주차장 현장을 설정하는 데스크톱 도구다. Python·PyQt5, 약 111,000줄, 테스트 파일 75개다. 층 도면 위에 도로·주차면·게이트·카메라·전광판을 그리고, 차량·보행 경로 그래프를 만들고, 카메라를 보정한다. 편집의 원본은 현장마다의 SQLite(`calibrationDB.db`)이고, YAML과 이미지는 거기서 내보내는 산출물이다. 외부 서버(IRIRO)와 주차면·경로를 맞추는 기능도 있다.

FlowMat은 공정 흐름을 그리고 재고·생산·품질을 운영하는 웹 서비스다. 그래서 겹치는 것은 화면의 업무가 아니라 **도구가 일하는 방식**이다. 편집 화면의 조작, 파일과 DB를 맞추는 절차, 외부에 적용하고 확인하는 절차가 그렇다.

## 2. 가져올 수 있는 범위

- **코드는 옮기지 않는다. 동작을 다시 만든다.** settingTool은 Python·PyQt5·SQLite이고 FlowMat은 Java·TypeScript·PostgreSQL이다. 가져온다는 말은 같은 동작을 FlowMat의 구조로 구현하고 테스트한다는 뜻이다.
- **settingTool에는 LICENSE 파일이 없다.** 같은 조직의 저장소이므로 동작을 참고하는 데는 문제가 없지만, 코드를 그대로 공개 저장소에 넣는 것은 소유자의 결정이 따로 필요하다.
- **넣지 않는 것:** `yolov8n-seg.pt`와 `ultralytics`(AGPL-3.0), 서브모듈 `apgs_imgproc`(APGS-Group 저장소). 라이선스와 소유를 확인하기 전에는 공개 FlowMat에 넣지 않는다(월간 계획 "위험").

## 4. 가져올 것과 순서

1. **가져오기에서 줄을 골라 적용(4주차, 첫 기능).** 지금은 CSV의 한 줄이 틀리면 전체가 막힌다. settingTool처럼 미리 보기에서 줄마다 적용 여부를 고르고, 틀린 줄은 그 줄만 빠지게 한다. 적용은 여전히 한 트랜잭션이다. 품목 가져오기부터 하고, 같은 방식을 재고·BOM 가져오기에 쓴다. 테스트는 고른 줄만 반영되는지, 틀린 줄을 뺀 나머지가 적용되는지, 다시 올리면 "unchanged"인지 본다.
2. **외부 적용 뒤 검증 보고(다음 달, FM-INT-002).** 연동 실행이 끝나면 대상을 다시 읽어 보낸 값과 맞는지 확인하고, 항목별로 성공·부분 성공·실패·확인 불가를 남긴다. settingTool의 주차면 Apply가 하는 순서 그대로다.
3. **도면 배치와 실제 거리(다음 달 후보, ADR 먼저).** 공장 도면을 프로젝트에 올리고 실측 크기를 정한 뒤 보관 위치·설비·공정을 그 위에 둔다. 경로 그래프의 구간 길이로 공정 사이 이동 시간을 계산해 연결의 지연 시간에 제안한다. 좌표는 settingTool처럼 도면 크기와 무관한 정규화 값으로 저장한다. 테이블과 화면이 새로 필요하므로 저장 위치와 범위를 ADR로 먼저 정한다.
4. **작은 것(여유가 있으면).** 공정 번호 일괄 부여, 목록에서 이름 이어서 고치기, `Shift` 축 고정. 각각 필요한지 먼저 확인한다.

이 문서의 "가져올 후보"가 모두 **있음** 또는 **가져오지 않음(이유)**이 되면 이 줄기는 끝난다.
