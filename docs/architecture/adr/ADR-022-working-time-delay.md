# ADR-022: 근무 시간으로 세는 연결 지연

작성일: 2026-10-19

## 상태

**Accepted (2026-10-19). 로컬 구현 2fa(2026-10-19, V99, `86949f0`에서 커밋).** [ADR-015](ADR-015-shift-aware-delay.md)가 남긴 "지연 시간 자체를 근무 시간으로만 셀지"를 골랐다(사용자 지시 "어떤기능이던 지금 구현된 기능과 연관된것 부터 처리해", 2026-10-18). 세부는 사용자 사전 위임(2026-10-18, "구현 중 새 설계 선택 | 권장안으로 진행")에 따라 리드가 고른 권장안이다.

근거: [ADR-010](ADR-010-connection-delay.md)(연결 지연), [ADR-015](ADR-015-shift-aware-delay.md)·[ADR-016](ADR-016-crew-aware-delay.md)(근무 시간에 맞춘 지연), [연결 계약](../../domain/process-port-connection-contract.md) GR-45–GR-58.

## 배경

경화·건조처럼 사람이 없어도 흐르는 시간과, 검사 대기처럼 일하는 동안만 흐르는 시간이 있다. 지금의 지연은 모두 앞의 것이다. 지연이 근무 밖에서 끝나면 다음 근무로 미루지만(ADR-015), 지연 자체는 밤에도 흐른다.

## 결정

| # | 결정 | 누가 |
|---|---|---|
| 1 | 연결마다 지연이 세는 시간을 고른다: `delayBasis` `elapsed`(모든 시간, 기본, 지금까지와 같음) 또는 `working`(작업지시의 설비와 인력이 함께 일하는 시간). 생성에서 빠지면 elapsed, 수정에서 빠지면 그대로다 | 사용자 사전 위임(2026-10-18) |
| 2 | `working` 지연은 생산 실행에 연결된 Flow Run에서, 앞 단계가 끝난 때(게이트웨이는 받은 때)부터 작업지시 설비의 가용 시간과 몫 100%이고 교대가 있는 인력이 모두 일하는 시간(ADR-015·016과 같은 시간)을 지연만큼 쌓은 때 끝난다. 그 시각이 다음 단계의 예정 시각이다. 근무 구간의 끝에 정확히 닿으면 ADR-015처럼 다음 근무 시작으로 미룬다 | 사용자 사전 위임(2026-10-18) |
| 3 | `working`인데 생산 실행이 아니거나, 작업지시·설비·그런 인력이 없거나, 1년 안에 그만큼의 근무 시간이 없으면 모든 시간으로 센다 | 사용자 사전 위임(2026-10-18) |
| 4 | `step_scheduled`에 `delayBasis: "working"`. 지연이 근무 시간 안에서 끝나므로 보통 미룸(`readyAt`)은 없고, 예정 시각 전의 바로 시작(ADR-015 결정 6)은 안 된다 | 사용자 사전 위임(2026-10-18) |
| 5 | 발행 snapshot의 연결에 `delayBasis`가 들어간다. 이 결정 전의 revision에는 없으므로 모든 시간이다. 그래서 `schemaVersion`은 3 그대로다 | 사용자 사전 위임(2026-10-18) |
| 6 | 편집기 연결 검사기에 **Delay counts**(All time / Working time). Working time이면 안내를 보인다 | 사용자 사전 위임(2026-10-18) |
| 7 | 새 마이그레이션 V99: `process_connection.delay_basis`(기본 `elapsed`, 검사 제약) | 사용자 사전 위임(2026-10-18) |

## 결과

- 좋은 점: 검사 대기처럼 일하는 동안만 흐르는 기다림을 그대로 그릴 수 있다. 기존 연결과 이미 발행한 revision은 바뀌지 않는다.
- 위험: V99가 V95–V98 뒤에 붙는다(2026-10-19 `86949f0`에서 함께 커밋). 열 하나와 검사 제약을 더한다.
