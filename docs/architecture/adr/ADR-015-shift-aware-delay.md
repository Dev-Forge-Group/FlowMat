# ADR-015: 근무 시간에 맞춘 연결 지연

작성일: 2026-10-18

## 상태

**Accepted (2026-10-18). 로컬 구현 2et(2026-10-18, 커밋 전, 마이그레이션 없음).** 핵심 두 가지는 사용자가 정했다(2026-10-18, 이번 주 결정 "근무 시간에 맞춘 지연", "작업지시 설비 달력"). 나머지 세부는 같은 날 사용자 사전 위임("구현 중 새 설계 선택 | 권장안으로 진행")에 따라 리드가 권장안을 골랐다. 표의 "누가"에 구분해 적는다.

근거: [ADR-010](ADR-010-connection-delay.md) "결정하지 않은 것" 셋째 항목, [ADR-011](ADR-011-production-steps.md)(생산 실행의 공정 단계), [ADR-014](ADR-014-equipment-calendar-history.md)(설비 달력 판), [설비 달력](../../domain/equipment-schedule.md) "계획 기간 제안"(가용 시간 = 교대 − 휴일 − 정지), [주간 계획](../../status/WEEK-PLAN-2026-10-19.md) "이번 주 결정".

## 배경

| # | 지금 | 근거 |
|---|---|---|
| P1 | 연결 지연이 있으면 다음 단계의 `scheduledAt` = 앞 단계 완료 + 지연이다. 그 전 `start`는 409다 | ADR-010 결정 1·6 |
| P2 | 지연은 근무와 상관없이 더한다. 금요일 16:00에 끝나고 2시간 식히면 다음 단계는 금요일 18:00부터다. 공장이 17:00에 닫아도 그렇다 | |
| P3 | 생산 실행에 연결된 Flow Run은 `productionRunId`를 가진다. 생산 실행은 작업지시를, 작업지시는 설비를 가질 수 있다 | ADR-011, 설비 E1–E4 |
| P4 | 설비의 가용 시간(교대 − 휴일 − 정지, 날짜마다 그날의 판)은 catalog가 이미 계산한다. 계획 기간 제안이 같은 계산을 쓴다 | H4, ADR-014 |
| P5 | flowrun은 production을 모른다. production이 flowrun 공개 API를 쓴다 | ADR-002, `ProductionFlowRunAdapter` |

## 결정

| # | 결정 | 누가 |
|---|---|---|
| 1 | 생산 실행에 연결된 Flow Run의 단계는 **작업지시 설비의 가용 시간**에 맞춘다. 작업지시나 설비가 없거나, 생산에 연결되지 않은 실행은 지금처럼 미루지 않는다 | 사용자 결정(2026-10-18 "작업지시 설비 달력") |
| 2 | 지연은 달력 시간 그대로 흐른다(식힘·굳힘은 밤에도 된다). 지연이 끝난 시각(`readyAt`)이 가용 시간 안이면 그대로, 밖이면 **다음 가용 시간의 시작**으로 미룬다 | 사용자 결정(2026-10-18 "근무 시간에 맞춘 지연") |
| 3 | 미루는 단계는 ADR-010으로 `scheduledAt`이 생기는 **일 단계**뿐이다. 지연 없는 단계는 지금처럼 바로 시작한다. 게이트웨이는 받은 시각을 그대로 넘기고(ADR-010 결정 4), 그 뒤 일 단계에서 한 번만 미룬다 | 사용자 사전 위임(2026-10-18) |
| 4 | `readyAt`의 날짜에 설비 달력이 없으면(항상 가동) 정지가 있어도 미루지 않는다. 설비가 지워졌거나 366일 안에 가용 시간이 없으면 `readyAt` 그대로 둔다 | 1의 "달력이 없으면 그대로"를 따름 + 사용자 사전 위임(2026-10-18) |
| 5 | 미뤘을 때 `step_scheduled` 이벤트에 `readyAt`(지연이 끝난 시각)과 `equipmentId`를 더한다. 화면의 지연 줄은 `· after a 2 h delay, then the equipment's next working time` | 사용자 사전 위임(2026-10-18) |
| 6 | 미룬 시각은 기본값이다. 생산 실행의 단계에는 `schedule` API가 없으므로, 지연이 끝났고 **지금 설비가 가용 시간이면**(그날의 날짜별 교대로 둔 야근 포함) 미룬 시각 전에도 시작할 수 있다. 그 밖에는 지금처럼 409 `Step cannot start before its scheduledAt.` | 사용자 사전 위임(2026-10-18). 첫 초안의 "`schedule`로 앞당김"은 생산 단계에 그 API가 없어 구현 전에 고쳤다 |
| 7 | 단계가 생길 때 한 번 정한다. 그 뒤 달력·정지·작업지시 설비가 바뀌어도 이미 정한 `scheduledAt`은 다시 계산하지 않는다 | 사용자 사전 위임(2026-10-18) |
| 8 | 의존 방향: flowrun 공개 API에 `LinkedRunWorkingTime`(묻는 쪽 인터페이스)을 두고 production이 구현한다. production은 catalog 공개 API `EquipmentWorkingTimeQuery`로 설비의 다음 가용 시각을 묻는다. 새 마이그레이션은 없다 | 사용자 사전 위임(2026-10-18) |

## 예

- 프레스 08:00–17:00 월–금. Mix가 금요일 16:00에 끝나고 연결 지연 2시간 → `readyAt` 금 18:00(근무 밖) → Bake `scheduledAt` 월 08:00. 이벤트에 `readyAt` 금 18:00, `equipmentId` 프레스.
- 같은 프레스에서 화요일 10:00에 끝나면 `readyAt` 화 12:00(근무 안) → 그대로 화 12:00.
- 작업지시에 설비가 없거나, 생산에 연결되지 않은 Flow Run이면 금 18:00 그대로.
- 금요일 19:00에 Bake를 시작하면 409다. 그날 프레스에 19:00–22:00 날짜별 교대(야근)를 두면 바로 시작할 수 있다(결정 6).

## 수용 기준 (2026-10-18)

- [x] 쓰는 달력: **작업지시 설비의 가용 시간**(사용자 결정)
- [x] 미루는 방식: **지연이 근무 밖에 끝나면 다음 근무 시작으로**(사용자 결정)
- [x] 대상 단계, 달력 없는 날, 기록, 앞당기기, 다시 계산하지 않음, 의존 방향: 결정 3–8(사용자 사전 위임)
- [x] 새 마이그레이션: **없음**

## 결정하지 않은 것

- 작업자 달력(필요한 사람, crew)까지 함께 맞출지
- 지연 시간 자체를 근무 시간으로만 셀지(지금은 달력 시간)
- 이미 정한 `scheduledAt`을 달력이 바뀔 때 다시 계산할지

## 결과

- 좋은 점
  - 근무가 끝난 뒤로 잡힌 단계가 없어져, 화면의 "언제부터"가 실제로 일할 수 있는 시각이 된다.
  - 계획 기간 제안과 같은 가용 시간 계산을 써서 숫자가 어긋나지 않는다.
- 위험
  - 단계가 생길 때 설비 달력을 한 번 더 계산한다. 앞 1주, 1달, 1년 순으로 좁게 먼저 찾는다.
  - 생산 실행의 단계 시작 시각이 지금보다 늦어질 수 있다. 설비에 그날 교대를 두면 바로 시작할 수 있다(결정 6).

## 구현 메모 (2026-10-18, 2et)

- catalog 공개 API `EquipmentWorkingTimeQuery.nextWorkingTime`(`EquipmentScheduleService`가 구현): 그 날짜에 달력이 없으면 그 시각 그대로, 있으면 계획 기간 제안과 같은 가용 시간(교대 − 휴일 − 정지)에서 그 시각 이후 첫 시각. 앞 7일, 31일, 366일 순으로 찾는다.
- flowrun 공개 API `LinkedRunWorkingTime`을 production의 `ProductionRunWorkingTime`이 구현한다(생산 실행 → 작업지시 → 설비). `FlowRunRouter`가 일 단계를 만들 때 묻고, 미뤘으면 `step_scheduled`에 `readyAt`·`equipmentId`를 더한다.
- 시작 확인(결정 6): `FlowRunStepService.start`가 예정 시각 전이면 `FlowRunRouter.mayStartEarly`에 묻는다. 그 단계의 마지막 `step_scheduled`에 `readyAt`이 있고, 그 시각이 지났고, 지금 설비가 가용 시간이면 시작한다.
- 화면: Flow Run 단계 줄은 `· after a 2 h delay, then the equipment's next working time`, 생산 실행의 Process steps는 아직 시작할 수 없는 계획 단계에 `· from <날짜 시각>`을 보인다.
- 검증은 [Flow Run](../../domain/flow-run.md) F13과 그 검증 문단.
