# ADR-024: 판의 저장 이력

작성일: 2026-10-19

## 상태

**Accepted (2026-10-19). 로컬 구현 2fc(2026-10-19, 커밋 전, V101).** [ADR-017](ADR-017-version-reasons.md)이 남긴 "판의 저장 이력(한 판을 여러 번 고친 기록)을 따로 남길지"를 골랐다(사용자 지시 "어떤기능이던 지금 구현된 기능과 연관된것 부터 처리해", 2026-10-18). 세부는 사용자 사전 위임(2026-10-18, "구현 중 새 설계 선택 | 권장안으로 진행")에 따라 리드가 고른 권장안이다.

근거: [ADR-013](ADR-013-rota-history.md)(근무표 판), [ADR-014](ADR-014-equipment-calendar-history.md)(설비 달력 판), [ADR-017](ADR-017-version-reasons.md)(판 사유), [작업자 달력](../../domain/worker-calendar.md) WC55–WC64, [설비 일정](../../domain/equipment-schedule.md) CV1–CV11.

## 배경

판은 마지막 저장만 남는다. 같은 날짜로 다시 저장하면 앞의 교대·사유·저장한 사람이 사라지고, 시작 전에 지운 판은 흔적이 없다.

## 결정

| # | 결정 | 누가 |
|---|---|---|
| 1 | 작업자 근무표 판과 설비 달력 판을 저장하거나 지울 때마다 이력 한 줄을 남긴다: 판, 시작일, `saved`·`removed`, 사유, 그때의 교대(작업자는 순환 근무표도), 누가, 언제. 저장과 같은 트랜잭션이다 | 사용자 사전 위임(2026-10-18) |
| 2 | 팀 근무표 복사(WC51)는 받는 사람마다 저장 한 줄이다. 설비 달력 지우기(`DELETE …/calendar?effectiveFrom=`)는 교대 없는 저장(그날부터 종일)이다 | 사용자 사전 위임(2026-10-18) |
| 3 | 이력은 판과 외래 키로 묶지 않는다. 지운 판의 줄도 남는다. V101 전의 저장은 줄이 없다 | 사용자 사전 위임(2026-10-18) |
| 4 | 조회: `GET /projects/{projectId}/workers/{userId}/schedule-history`, `GET /equipments/{equipmentId}/calendar/history`. 프로젝트 읽기 권한, 최신 순 100줄까지. 이력은 고치거나 지우지 않는다 | 사용자 사전 위임(2026-10-18) |
| 5 | 화면: Workers의 **Version history**, 설비 일정의 **Calendar history**(접어 두고 열 때 불러옴). 한 줄에 시각·누가·저장/지움·시작일·교대·사유 | 사용자 사전 위임(2026-10-18) |
| 6 | 새 마이그레이션 V101: `worker_schedule_history`, `equipment_schedule_history`(교대는 jsonb) | 사용자 사전 위임(2026-10-18) |

## 수용 기준 (2026-10-19)

- [x] 기록: 결정 1–3(WC63, CV10)
- [x] 조회와 화면: 결정 4·5(WC64, CV11)
- [x] 마이그레이션: V101, 채울 값 없음

## 결정하지 않은 것

- 날짜별 교대·쉬는 날·정지의 저장 이력
- 이력을 얼마나 오래 둘지(지금은 지우지 않는다)

## 결과

- 좋은 점: 근무표·설비 달력을 누가 언제 어떻게 바꿨는지, 지운 판이 무엇이었는지 남는다.
- 위험: V101이 커밋 전 마이그레이션(V95–V101)에 붙는다. 새 표 둘만 만든다. 저장마다 줄이 늘어난다(조회는 100줄까지).
