# ADR-020: 끝난 실행의 작업자 시간 보정

작성일: 2026-10-19

## 상태

**Accepted (2026-10-19). 로컬 구현 2ey(2026-10-19, V97, `86949f0`에서 커밋).** [ADR-019](ADR-019-run-labor.md)가 남긴 "끝난 실행의 작업자 시간 보정"을 골랐다(사용자 지시 "어떤기능이던 지금 구현된 기능과 연관된것 부터 처리해", 2026-10-18). 세부는 사용자 사전 위임(2026-10-18, "구현 중 새 설계 선택 | 권장안으로 진행")에 따라 리드가 고른 권장안이다.

근거: [실행 보정](../../domain/production-run-correction.md), [설비 가동 시간 보정](../../domain/equipment-setup-cost.md) ER10–ER12, [작업자 달력](../../domain/worker-calendar.md) LB9–LB11.

## 결정

| # | 결정 | 누가 |
|---|---|---|
| 1 | 끝난 실행의 작업자 시간은 실행 보정으로만 바꾼다. 줄 종류는 `cancel_labor`(취소할 기록)와 `add_labor`(사람과 분). 설비 가동 시간 보정(ER10)과 같은 방식이다 | 사용자 사전 위임(2026-10-18) |
| 2 | 추가 줄에는 사람을 반드시 적는다. 실행 기록(LB2)처럼 부른 사람으로 채우지 않는다. 보정은 대개 다른 사람이 나중에 요청하기 때문이다 | 사용자 사전 위임(2026-10-18) |
| 3 | 반영은 소유자가 승인할 때, 재고 줄 뒤에 setup·가동 시간과 함께 한다. 취소 사유와 추가 기록의 메모는 `Correction #N: 사유`이고, 추가 기록의 기록자는 승인한 사람이다 | 사용자 사전 위임(2026-10-18) |
| 4 | 보정 요청 본문이 JSON이 아니거나 수량·분이 수가 아니면 400이다(전에는 500). 분은 정확한 정수만 받는다 | 사용자 사전 위임(2026-10-18) |
| 5 | 새 마이그레이션 V97: 보정 줄에 `target_run_labor_id`, `labor_user_id`, `worked_minutes`, `created_run_labor_id`를 더하고, 줄 종류 검사를 새로 바꾼다(V76의 검사는 고치지 않는다) | 사용자 사전 위임(2026-10-18) |

## 결정하지 않은 것

- 작업자 단가와 인건비(ADR-019와 같다). [ADR-025](ADR-025-worker-labor-cost.md)에서 정했다(2026-10-23, 로컬 구현 2ff)

## 결과

- 좋은 점: 끝난 실행의 작업자 시간도 설비 시간처럼 승인을 거쳐 바로잡는다. 원래 기록은 사유와 함께 남는다.
- 위험: V97이 V95–V96 뒤에 붙는다(2026-10-19 `86949f0`에서 함께 커밋). 열 추가와 검사 교체뿐이다.
