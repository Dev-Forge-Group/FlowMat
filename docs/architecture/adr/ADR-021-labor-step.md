# ADR-021: 생산 단계의 작업자 시간

작성일: 2026-10-19

## 상태

**Accepted (2026-10-19). 로컬 구현 2ez(2026-10-19, 커밋 전, V98).** [ADR-019](ADR-019-run-labor.md)가 남긴 "생산 단계(2el)별 작업자 시간"을 골랐다(사용자 지시 "어떤기능이던 지금 구현된 기능과 연관된것 부터 처리해", 2026-10-18). 세부는 사용자 사전 위임(2026-10-18, "구현 중 새 설계 선택 | 권장안으로 진행")에 따라 리드가 고른 권장안이다.

근거: [ADR-011](ADR-011-production-steps.md)(생산 실행의 공정 단계), [작업자 달력](../../domain/worker-calendar.md) LB1–LB16.

## 결정

| # | 결정 | 누가 |
|---|---|---|
| 1 | 작업자 시간 기록은 실행의 공정 단계 하나를 고를 수 있다(`stepId`). 고르지 않으면 지금처럼 실행 전체의 시간이다 | 사용자 사전 위임(2026-10-18) |
| 2 | 단계는 그 실행에 연결된 Flow Run의 공정 단계여야 한다(게이트웨이 제외). 단계는 flowrun 모듈의 것이라 외래 키 없이 공개 API로 확인한다 | 사용자 사전 위임(2026-10-18) |
| 3 | 응답에 단계 목록(시작·끝·그 단계에 센 분)과 기록마다 단계 이름을 둔다 | 사용자 사전 위임(2026-10-18) |
| 4 | 화면은 시작한 단계만 고르게 하고, 고르면 분은 그 단계의 시간(시작부터 끝, 진행 중이면 지금까지) × 몫 − 그 사람이 그 단계에 이미 센 분에서 시작한다. 계산은 화면이 한다(서버의 실행 단위 제안 LB4는 그대로) | 사용자 사전 위임(2026-10-18) |
| 5 | 보정 줄(`add_labor`, ADR-020)은 단계를 받지 않는다. 실행 전체의 시간으로 더한다 | 사용자 사전 위임(2026-10-18) |
| 6 | 새 마이그레이션 V98: `production_run_labor.step_id`(NULL 허용) | 사용자 사전 위임(2026-10-18) |

## 수용 기준 (2026-10-19)

- [x] 기록과 검사: 결정 1·2(LB13–LB14)
- [x] 응답과 화면: 결정 3·4(LB15–LB16)
- [x] 마이그레이션: V98, 채울 값 없음

## 결정하지 않은 것

- 보정 줄에서 단계를 고르는 것. [ADR-023](ADR-023-labor-step-followups.md)에서 정했다(2026-10-19)
- 단계의 작업자 시간을 작업지시 대비(LB6)에 단계별로 나눠 보이는 것. [ADR-023](ADR-023-labor-step-followups.md)에서 실제 분을 공정별로 더하게 했다(2026-10-19)

## 결과

- 좋은 점: 누가 어느 공정에서 얼마나 일했는지 남는다. 단계의 실제 시간이 분의 시작값이 되어 입력이 빠르다.
- 위험: V98이 커밋 전 마이그레이션(V95–V98)에 붙는다. 열 하나만 더한다.
