# ADR-008: 수량 분할(Split) 게이트웨이

작성일: 2026-10-17

## 상태

**Accepted (2026-10-17, 사용자 결정 "Accept as recommended"). 로컬 구현 2eh(2026-10-17, V89, 2026-10-18 `9500678`에서 커밋).** 같은 날 사용자 요청("Quantity split ADR draft")으로 Proposed 초안을 썼고, 사용자가 권장안 그대로 수용 기준 8개를 닫았다. [ADR-006](ADR-006-operation-types.md)과 [ADR-007](ADR-007-join-gateway.md)이 "결정하지 않은 것"으로 넘긴 수량 분할(SPLIT)과 갈래별 수량 배분을 아래 결정으로 정한다. 승인과 구현은 별개다.

근거: [ADR-006](ADR-006-operation-types.md)(게이트웨이 노드), [ADR-007](ADR-007-join-gateway.md)(Join, 합친 수량), [연결 계약](../../domain/process-port-connection-contract.md) GR-02–GR-04·GR-24, [ADR-005](ADR-005-port-measurement-and-validation.md)(포트 계측), [벤치마크](../../reference/benchmarks/FlowMat_GitHub_Benchmark_2026-09-24.md) FM-PLAN-001(SPLIT, frePPLe split operation). 코드는 가져오지 않는다.

## 배경 (2026-10-17 코드 기준)

| # | 지금 동작 | 근거 |
|---|---|---|
| S1 | 출발 단계가 완료되면 통과한 연결마다 **같은** 출력 스냅샷이 간다. 조건 없는 연결 둘이면 두 갈래가 같은 `quantity`를 받는다. 수량이 나뉘지 않고 복제된다 | GR-04 |
| S2 | 연결의 `capacity`는 그 연결로 가는 `quantity`의 상한이고, 넘으면 완료 보고 전체를 거절한다 | GR-03 |
| S3 | Join은 같은 단위의 도착 수량을 더한다. 그래서 복제된 병렬 갈래를 Join으로 모으면 수량이 갈래 수만큼 커진다 | GR-24 |
| S4 | 연결의 `flowRate`·`lossRate`·`delayTimeSec`는 저장만 하고 실행에 쓰지 않는다 | [현재 기능](../../status/CURRENT_CAPABILITIES.md) FM-FLOW-002 |
| S5 | 그래프 실행 단계는 스냅샷만 나른다. 재고·생산 기록은 생산 실행이 따로 움직인다 | [실행 모델](../execution-model.md) §6·§8 |
| S6 | 단위에는 소수 자릿수 정의가 없다(`unit_master`는 종류·기준 단위·환산율만). 연결 용량은 `numeric(19,4)`다 | `UnitMaster`, PC-14 |
| S7 | 게이트웨이(Exclusive·Join)는 서버가 system으로 지나가고, 출력이 연결 규칙을 어기면 계기가 보고일 때 409, 시스템 계기일 때 실행 실패다 | ADR-006 결정 4, ADR-007 결정 9 |

S1과 S3이 이 결정의 이유다. 재료를 두 공정으로 나눠 보내는 흐름을 지금 그리면 양쪽이 전량을 받은 것으로 기록되고, 다시 모으면 두 배가 된다.

## 선택지: 어디서 나누는가

| 안 | 내용 | 좋은 점 | 약점 |
|---|---|---|---|
| A. Split 게이트웨이 노드 | ADR-006의 게이트웨이 계열에 노드 종류 `split`을 더하고, 나가는 연결마다 몫(비율·고정량·나머지)을 둔다 | 나누는 곳이 그림에 보인다. 일반 노드의 동작(S1)은 그대로다 | 노드가 하나 더 생긴다 |
| B. 연결의 몫 | 어느 노드든 나가는 연결에 몫을 두면 그 노드의 출력을 나눈다 | 노드가 늘지 않는다 | 한 노드에서 몫 있는 연결과 없는 연결이 섞이거나, 조건과 몫이 함께 있으면 해석이 어렵다 |
| C. 보고 때 나누기 | 완료 보고에 연결마다 수량을 적는다(`outputSnapshot.routes[{connectionId, quantity}]`) | 정해진 비율이 없는 공정(실측 분배)에 맞다 | 규칙이 그림에 없고, 보고하는 쪽이 매번 맞춰야 한다 |

## 결정 (2026-10-17, 권장안 그대로)

1. **A(Split 게이트웨이).** 노드 종류 `split`. 일반 노드의 복제 동작(S1)은 그대로 둔다.
2. **몫의 종류:** 나가는 연결마다 하나를 둔다. `share`(입력 수량의 %, 0 초과 100 이하, 소수 2자리), `fixed`(고정 수량, 0 초과), `rest`(나머지, Split마다 최대 하나).
3. **계산 순서:** 비율 몫은 입력 전체에 대한 %로 센다. 나머지 = 입력 − 고정량 합 − 비율 몫 합. 고정량과 비율 몫의 합이 입력을 넘으면 아래 6처럼 실패한다.
4. **반올림:** 각 몫을 소수 4자리로 반올림한다(HALF_UP, 연결 용량과 같은 자릿수, S6). 반올림 차이는 나머지 연결이 가진다. 나머지 연결이 없으면(비율 합이 정확히 100) 그린 순서로 마지막 비율 연결이 가진다. 그래서 몫의 합은 언제나 입력과 같다.
5. **0인 몫:** 그 연결로는 단계를 만들지 않고 `connection_filtered`(reason `split_empty`)를 남긴다.
6. **조건과 실패:** Split에서 나가는 연결에는 조건식을 두지 않는다(발행 오류). 입력에 수인 `quantity`가 없거나 고정량·비율 몫이 입력을 넘으면, 계기가 완료 보고일 때는 그 보고를 409로 거절한다. Join 뒤처럼 사람이 다시 보낼 수 없는 계기일 때는 Split 단계가 `SPLIT_REJECTED`로 실패하고 실행도 실패한다(ADR-007 결정 9와 같은 규칙).
7. **각 갈래의 스냅샷:** 입력을 그대로 복사하고 `quantity`만 그 몫으로 바꾼다. `unit`·`item`·`attrs`는 그대로다. 연결 용량·단위·포트 규칙(GR-03·GR-07·GR-08)은 각 몫으로 본다.
8. **서버 통과:** Split 단계는 Exclusive처럼 서버가 system으로 바로 지나간다(ADR-006 결정 4의 예외를 Split에 넓힌다). 재고·생산 기록은 움직이지 않는다.
9. **발행 검사:** 오류 `SPLIT_WITHOUT_INPUT`(진입 연결 없음), `SPLIT_SHARE_MISSING`(몫이 없는 연결), `SPLIT_REST_DUPLICATE`(나머지 둘 이상), `SPLIT_SHARES_OVER`(비율 합 100 초과), `SPLIT_NO_REST`(나머지 연결이 없는데 고정량이 있거나 비율 합이 100이 아님), `SPLIT_CONDITION`(조건식). 경고 `SPLIT_SINGLE_ROUTE`(나가는 연결 하나). 기본 연결 표시는 지금처럼 Exclusive에서만이다(GR-19).
10. **저장:** 연결에 `split_kind`(`share`·`fixed`·`rest`)와 `split_value`(numeric(19,4)) 열을 둔다. 새 마이그레이션이 필요하다. 발행 snapshot에 들어가고 실행 중에는 바뀌지 않는다(ADR-003 결정 5와 같은 원칙).
11. **화면:** 팔레트에 **Split**. Split에서 나가는 연결 인스펙터에 **Share**(% · fixed · rest)와 값. 실행 화면의 각 갈래 단계에는 받은 수량이 보인다.
12. **Join과의 관계:** Split으로 나눈 갈래를 Join이 모으면 같은 단위의 합이 다시 입력과 같다. 손실은 아직 반영하지 않는다(S4).

## 예

- 비율: 100 kg → A 70% · B 30% → 70 · 30.
- 고정과 나머지: 100 kg → 시료 0.5 kg(fixed) · 본류(rest) → 0.5 · 99.5.
- 반올림: 10 ea → 33.33% · 33.33% · rest → 3.333 · 3.333 · 3.334. 개수 단위라도 지금은 소수 4자리다(아래 "결정하지 않은 것").
- 모자람: 2 kg → fixed 3 kg → 완료 보고면 409, 시스템 계기면 실행 실패.

## 결정하지 않은 것

- 개수 단위(ea)의 정수 나눔(단위에 자릿수 정의가 생긴 뒤)
- 손실률(`lossRate`)·흐름률 적용
- 보고 때 나누기(안 C)를 Split의 덮어쓰기로 허용할지
- 품목이 바뀌는 분할(부산물·폐기물)은 BOM·생산 실행 쪽 규칙([실행 모델](../execution-model.md) §6)

## 결과

- 좋은 점
  - 병렬 갈래가 수량을 복제하지 않고 나눌 수 있고, Join으로 모으면 다시 같은 합이 된다.
  - 일반 노드와 이전 revision의 동작은 그대로다.
- 위험
  - 반올림 차이를 어디에 두느냐가 결과 숫자를 바꾼다. 그래서 규칙을 하나로 고정한다(결정 4).
  - 연결 저장·편집기·발행 검사·실행이 함께 바뀐다.
  - 서버가 스스로 완료하는 게이트웨이가 하나 더 생긴다.
