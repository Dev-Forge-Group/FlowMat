# ADR-034: BOM 줄 실제 손실 집계

작성일: 2026-11-02

## 상태

**Accepted (2026-11-02). 로컬 구현 2hy(마이그레이션 없음, 읽기 전용, 커밋 전).**

## 배경

- 줄 스크랩률(ADR-031)은 계획값이다. 실제로 얼마나 잃는지는 실행마다 사용량 차이 화면에서만 보인다.
- 스크랩률을 고치려면 같은 revision의 여러 실행을 모아 "계획 5%, 실제 8%"처럼 봐야 한다. 지금은 실행을 하나씩 열어 손으로 더해야 한다.
- 두 사용자 모두에게 필요하다. 생산관리자는 스크랩률을 실제에 맞게 고치고, 개발자는 계획 소요량이 실제와 얼마나 어긋나는지 데이터로 본다.

## 선택지

- A: **revision 하나의 끝난 실행을 모아 줄별로 보인다.** 저장 없이 조회 때 계산한다.
- B: 제품 단위로 revision을 가로질러 모은다. revision마다 스크랩률이 달라 비교 기준이 섞인다.
- C: 실행이 끝날 때 줄별 손실을 표에 저장한다. 마이그레이션이 필요하고, 실행 보정 때 다시 맞춰야 한다.

**권장안: A.** 같은 스크랩률 아래의 실적만 모으므로 비교가 바로 읽히고, 저장이 없어 실행 보정·취소가 바로 반영된다. 새 revision을 만들 때는 이전 revision의 숫자를 보고 고친다.

## 결정

1. **대상 실행.** 그 revision으로 시작한 물리 실행 가운데 끝났고(finished), 계획·실제 생산량이 0보다 큰 것. 시뮬레이션, 진행 중, 삭제된 실행은 뺀다.
2. **대상 줄.** 실행 계획 행(`quantity_source='bom'`) 가운데 revision 자신의 자재 줄에서 온 것(팬텀을 거친 행은 뺀다). 선택 자재는 그 실행이 계획에 넣었을 때만 센다(ADR-033).
3. **양.** 실행마다 실제 생산량에 맞춘다.
   - 계획량 = 계획 행 × 실제 생산량 ÷ 계획 생산량(스크랩 포함).
   - 순량 = 계획량 ÷ (1 + 줄 스크랩률).
   - 실제량 = 취소되지 않은 실제 투입을 품목 단위로 바꾼 합. 승인된 대체 자재 투입은 주 자재 몫으로 더한다(ADR-032 결정 2).
4. **비율.** 실제 손실률 = 실제량 합 ÷ 순량 합 − 1(소수 넷째 자리)이다. 계획 스크랩률과 나란히 보인다. 음수면 순량보다 적게 쓴 것이다.
5. **단위를 바꿀 수 없는 투입**이 있으면 그 줄은 불완전(`complete=false`)으로 표시하고 그 투입은 뺀다.
6. **API·화면.** `GET /boms/{bomId}/scrap-performance`(BOM 읽기 권한). BOM 화면의 승인·은퇴 revision에 "Scrap: planned vs actual" 표를 보인다(끝난 실행이 있을 때).

## 결정하지 않은 것

- 기간 필터와 제품 단위 집계(선택지 B).
- 팬텀 BOM 안 자재의 손실.
- 실제 손실로 스크랩률을 자동 제안·수정하는 것.

## 결과

- 같은 revision의 끝난 실행을 모아 자재마다 계획 스크랩률과 실제 손실률을 나란히 본다. 저장이 없어 실행 보정·취소가 바로 반영된다.
- ADR-031의 "결정하지 않은 것"은 모두 정리됐다(대체 ADR-032, 선택 ADR-033, 실제 손실 ADR-034).
