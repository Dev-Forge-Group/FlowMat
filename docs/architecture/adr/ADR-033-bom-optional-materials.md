# ADR-033: BOM 선택 자재

작성일: 2026-11-02

## 상태

**Accepted (2026-11-02). 로컬 구현 2hx(마이그레이션 V133, 커밋 전, V133 개발 DB 미적용).**
- 결정 1–10은 리드가 권장안으로 정했다. 근거는 2026-10-24 사용자 위임("의사결정도 recommend 로 계속 알아서 밀고나가")이다.
- 기존 동작을 바꾸지 않는다. 선택 자재 줄은 지금까지 승인이 거절했으므로 승인 revision에는 하나도 없다.
- V133은 새 표만 만든다(기존 표·행은 그대로). 개발 DB 5434에는 사용자가 커밋한 뒤 리허설을 거쳐 적용한다.
- 수용 기준이 모두 닫혀 같은 날 Proposed에서 Accepted로 올렸다.

## 배경 (2026-11-02 코드·개발 DB 기준)

- **열은 V1부터 있다.** `bom_line.optional_yn char(1) DEFAULT 'N'`이다. 줄 추가 API가 저장하지만 승인이 "optional materials are not supported yet"로 거절한다. 개발 DB 줄 48개는 모두 N이다.
- **작업지시의 BOM revision은 바뀔 수 있다.** 초안은 BOM을 비워 둘 수 있고, 승인·일정 변경 때 계획일의 유효 revision으로 정해진다([`WorkOrderBomSelection`](../../../flowmat_backend/modules/production/src/main/java/org/myweb/flowmat/domain/production/application/WorkOrderBomSelection.java)). 그래서 BOM 줄 id로 선택을 저장하면 revision이 바뀔 때 끊긴다.
- **승인된 작업지시는 고치지 않는다.** 수정 API는 초안만 받는다.
- **선택을 둘 곳이 없다.** 작업지시마다 넣을지를 저장하려면 새 저장소가 필요하다.
- **두 사용자 모두에게 필요하다.**
  - 생산관리자: "선물 상자는 그 주문에만", "고객 사양에 따라 첨가제" 같은 자재를 BOM 하나로 다룬다. 지금은 BOM을 둘 만들거나, 계획에 없이 투입해 부족·원가가 어긋난다.
  - 개발자: 작업지시마다 무엇을 넣는지가 데이터로 남아야 계획·차이·원가가 같은 근거를 쓴다.

## 선택지

- A: **작업지시가 고른다(기본 제외).** 고른 선택 자재만 그 작업지시의 계획에 들어간다. 새 표에 품목으로 저장한다.
- B: **기본 포함, 작업지시가 뺀다.** 저장은 A와 같고 기본값만 반대다.
- C: **계획에 넣지 않는다.** 선택 자재는 BOM에 기록만 하고, 쓰면 실적 투입으로만 남긴다. 저장소가 필요 없다.

**권장안: A.**
- "선택"의 뜻이 "넣지 않아도 된다"이므로, 고르지 않으면 계획에 없는 것이 읽기 쉽다.
- B는 고르지 않은 주문까지 선택 자재를 사고 예약한다(선물 상자가 10% 주문에만 들어가도 전부 산다).
- C는 지금과 거의 같아 계획·부족·예약에 도움이 없다.
- 품목으로 저장하면 revision이 바뀌어도 선택이 이어진다. 한 revision에 같은 품목은 한 번만 나온다(조건 5).

## 결정

1. **선택 자재.** `optional_yn = 'Y'`인 자재 줄이다. 부산물·폐기물 줄은 선택 자재일 수 없다. 대체 묶음에 들 수 없다(대체와 선택을 겹치지 않는다). 팬텀 줄은 선택 자재일 수 있다(고르면 팬텀 BOM으로 펼쳐진다).
2. **기본은 넣지 않는다.** 작업지시가 고른 선택 자재만 그 작업지시의 계획에 들어간다.
3. **저장.** 새 표 `work_order_optional_item(work_order_id, item_id)`(V133)에 품목으로 저장한다. 작업지시를 지우면 함께 지워진다.
4. **고르는 때.**
   - 작업지시를 만들 때와 초안을 고칠 때 `optionalItemIds`로 준다. 승인된 작업지시는 지금처럼 고치지 않는다.
   - 수정 요청에 `optionalItemIds`가 없으면(null) 그대로 두고, 빈 목록이면 모두 뺀다.
5. **검사.**
   - 고른 품목은 작업지시 BOM에서(팬텀 BOM 안 포함, 팬텀은 계획일 revision) 선택 자재여야 한다.
   - 저장 때 BOM이 정해져 있으면 검사한다. 승인 때 정해진 BOM으로 다시 검사하고, 맞지 않으면 승인을 거절한다.
6. **작업지시의 계산은 그 선택을 쓴다.** 준비 점검, 간이 MRP, 자동 할당, 창고 피킹, 실행 계획 투입, 폐기 처리. 선택은 팬텀 BOM 안의 선택 자재에도 같은 품목으로 적용된다.
7. **작업지시가 없는 계산은 선택 자재를 넣지 않는다.** BOM 화면 소요량, 만들 수 있는 양, 원가 누적, 다단계 역전개 합계, 작업지시 없는 실행, 하위 반제품 전개. 소요량 응답은 넣지 않은 선택 자재를 `optionals`로 따로 싣는다(같은 생산 수량의 양·원가).
8. **사용량 차이.** 실행 계획에 들어간 선택 자재는 다른 BOM 줄과 같다. 고르지 않은 선택 자재를 썼으면 기준 0인 것은 지금과 같고, "BOM 밖" 대신 "고르지 않은 선택 자재"로 표시한다(`optional` 참).
9. **화면.**
   - BOM 줄 추가에 "Optional" 체크(자재 줄, 대체 아님). 줄과 소요량에 선택 자재를 따로 보인다.
   - 작업지시 폼에 그 BOM(정하지 않았으면 계획일 유효 BOM)의 선택 자재 체크. 목록에 고른 선택 자재를 보인다.
10. **자재 CSV는 아직 선택 열을 받지 않는다.** `optional` 열이 있으면 파일을 거절한다(조용히 무시하지 않는다).

## 결정하지 않은 것

- **선택 자재의 기본 포함 여부를 줄마다 두는 것.**
- **승인된 작업지시의 선택 변경.** 지금은 초안에서만 바꾼다.
- **자재 CSV의 선택 열.**
- **원가 누적의 "선택 포함" 원가.** 지금은 기본(선택 제외) 원가만 보인다.

## 결과

- 작업지시마다 넣을 선택 자재를 품목으로 고르고, 그 작업지시의 계획·예약·실행 계획에만 들어간다. 고르지 않은 작업지시와 작업지시 없는 계산은 지금과 같다.
- 새 표 V133은 개발 DB 5434에 아직 적용하지 않았다. 사용자가 커밋한 뒤 복제본 리허설을 거쳐 적용한다.
