# ADR-025: 작업자 인건비

작성일: 2026-10-23

## 상태

**Accepted (2026-10-23). 로컬 구현 2ff(2026-10-23, 커밋 전, V103).** 사용자 계획 "10. 그 다음 Worker Labor Cost ADR owner-only monetary access project-scoped effective rate history"(2026-10-19)가 세 가지를 정했다. 금액은 소유자만 보고, 단가는 프로젝트마다 따로 두며, 적용 시작일이 있는 이력으로 남긴다(결정 1–3). 나머지 세부는 사용자 사전 위임(2026-10-18, "구현 중 새 설계 선택 | 권장안으로 진행")에 따라 리드가 고른 권장안이다. 구현은 2ff이고 새 마이그레이션은 V103이다(V102와 함께 커밋 전).

근거: [ADR-019](ADR-019-run-labor.md) "결정하지 않은 것: 작업자 단가와 인건비", [ADR-020](ADR-020-labor-correction.md), [작업자 달력](../../domain/worker-calendar.md) LB1–LB18, 같은 일을 설비에 대해 정한 [설비 원가](../../domain/equipment-setup-cost.md) AS2·AS8–AS10.

## 배경

실행 작업자 시간(2ex)은 분만 남긴다(LB5). 설비는 시간당 원가와 그 이력이 있어 setup·가동 시간에 금액이 붙지만, 작업자 단가는 없다. 사람의 단가는 급여 정보라 설비 원가처럼 프로젝트 읽기 권한으로 보이면 안 된다.

## 결정

| # | 결정 | 누가 |
|---|---|---|
| 1 | **금액은 프로젝트 소유자만** 읽고 쓴다. 단가와 인건비 금액을 다루는 API는 모두 `requireProjectOwnerAccess`다. editor·viewer와 작업자 본인도 단가를 보지 못한다 | 사용자(2026-10-19) |
| 2 | 단가는 **프로젝트 × 작업자**마다 둔다. 같은 사람도 프로젝트가 다르면 단가가 다르고, 다른 프로젝트의 단가는 읽지 않는다. 시간당 금액(소수 4자리, 0 이상). 비우면 미상이다(0과 다르다, 설비 AS9와 같음). 통화 열은 두지 않는다(설비 원가와 같음) | 사용자(2026-10-19) |
| 3 | 단가는 **적용 시작일이 있는 이력**이다. 한 줄 = 단가, 적용 시작일(프로젝트 날짜, 비우면 오늘), 사유, 누가, 언제. 새 단가는 앞의 줄을 지우지 않고 그 날짜부터 덮는다. 같은 시작일로 다시 저장하면 새 줄이 이기고 앞의 줄은 이력에 남는다 | 사용자(2026-10-19) |
| 4 | 시작일은 오늘(프로젝트 날짜) 이후만 받는다. 그래서 이미 지난 날짜의 금액은 바뀌지 않는다. 시작 전인 단가는 지울 수 있고, 지운 줄도 지운 사람·시각과 함께 남는다(판 ADR-013 결정 4와 같은 원칙) | 사용자 사전 위임(2026-10-18) |
| 5 | 금액은 저장하지 않고 읽을 때 계산한다: 작업자 시간 줄의 분 × 그 줄을 기록한 날(프로젝트 날짜)에 적용되던 단가 / 60, 소수 4자리 HALF_UP. 보정으로 더한 시간은 실행의 원래 마감 날짜의 단가를 쓴다(설비 AS8과 같은 원칙). 단가가 없으면 그 줄은 금액 미상이고 합계는 `costComplete=false`다 | 사용자 사전 위임(2026-10-18) |
| 6 | 금액은 새 소유자 전용 엔드포인트로만 낸다. 지금의 `GET /production-runs/{id}/labor`·`GET /work-orders/{id}/labor-comparison`은 금액 없이 그대로 두어, 소유자가 아닌 사람에게 가는 응답에는 금액 필드가 생기지 않는다. 후보: `GET·PUT /projects/{projectId}/workers/{userId}/labor-rates`, `DELETE …/labor-rates/{rateId}`, `GET /production-runs/{id}/labor-cost`, `GET /work-orders/{id}/labor-cost` | 사용자 사전 위임(2026-10-18) |
| 7 | 생산 쪽은 workforce 공개 API(예: `WorkerLaborRateQuery.rateOn(projectId, userId, date)`)로 단가를 읽는다. 다른 도메인의 엔티티·repository는 쓰지 않는다(단계 B·C, [ADR-018](ADR-018-entity-boundary.md)) | 사용자 사전 위임(2026-10-18) |
| 8 | 화면: 소유자에게만 Workers 카드의 **Labor rate**(지금·예정 단가와 이력), 실행 상세 작업자 시간의 금액, 작업지시 인력 대비의 금액. 다른 사람에게는 그 자리가 없다(숨긴 값을 내려받지 않는다) | 사용자 사전 위임(2026-10-18) |
| 9 | 인건비는 재료비(`/cost`)·단위 원가에 더하지 않고 따로 보인다(LB5 그대로) | 사용자 사전 위임(2026-10-18) |
| 10 | 인건비는 단위 원가나 작업지시 원가 합계에도 넣지 않는다. setup·가동 원가를 재료비에 합치지 않은 원칙(DECISIONS-2026-10-05 §4, 설비 ER5·ER13)과 같다. 여러 비용을 한데 더하는 합계는 그 원칙을 바꾸는 사용자 결정으로 남긴다 | 사용자 사전 위임(2026-10-18), 사용자 "ㄱ"(2026-10-23) |
| 11 | 작업자의 **첫 단가만** `fromStart: true`로 처음부터 적용할 수 있다(이미 기록된 작업자 시간에 금액이 생긴다). 미상이던 금액을 채울 뿐 정해진 금액은 바꾸지 않으므로 결정 4와 맞는다. 지우지 않은 단가가 하나라도 있으면 409, `effectiveFrom`과 함께 주면 400. 처음부터인 단가는 시작한 것이라 지울 수 없다 | 사용자 사전 위임(2026-10-18), 사용자 "ㄱ"(2026-10-23), 로컬 구현 2fh |

- [x] 이력: 적용 시작일, 지난 날짜 불변, 지운 줄 보존(결정 3, 4)
- [x] 금액 계산과 보정(결정 5)
- [x] 구현(2ff, 2026-10-23): V103 `worker_labor_rate`, 소유자 외 403과 작업자 시간 응답에 금액 없음, 지난 날짜 거절, 같은 날짜 재저장, 시작 전 지우기, 보정의 마감 날짜 단가(LB19–LB22)

- ~~인건비를 단위 원가나 작업지시 원가 합계에 넣을지~~ → 결정 10(넣지 않는다, 2026-10-23)
- 통화와 여러 통화
- 초과 근무·야간 할증 같은 단가 규칙
- 프로젝트 소유자가 바뀔 때 이전 소유자의 접근(지금 규칙으로는 바로 잃는다)
- 단가를 얼마나 오래 둘지(지우지 않는다)

## 결과

- 좋은 점: 작업자 시간에 금액이 붙어 설비 원가와 나란히 볼 수 있다. 급여 정보가 소유자 밖으로 나가지 않는다.
- 위험: 소유자 전용 응답과 일반 응답이 갈라져 화면이 두 갈래가 된다. 읽을 때 계산하므로 단가 조회가 실행·작업지시마다 한 번 더 든다(작업자별로 한 번에 읽는다). 새 마이그레이션이 하나 는다.
