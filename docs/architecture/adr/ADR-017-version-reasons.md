# ADR-017: 판을 바꾼 사유

작성일: 2026-10-18

## 상태

**Accepted (2026-10-18). 로컬 구현 2ev(2026-10-18, 커밋 전, V95).** 사용자 지시("어떤기능이던 지금 구현된 기능과 연관된것 부터 처리해", 2026-10-18)에 따라 [ADR-013](ADR-013-rota-history.md)과 [ADR-014](ADR-014-equipment-calendar-history.md)가 함께 남긴 "판마다 바꾼 사유를 받을지"를 골랐다. 세부는 같은 날 사용자 사전 위임("구현 중 새 설계 선택 | 권장안으로 진행")에 따라 리드가 고른 권장안이다.

근거: [ADR-013](ADR-013-rota-history.md), [ADR-014](ADR-014-equipment-calendar-history.md), [작업자 달력](../../domain/worker-calendar.md) WC55–WC60, [설비 달력](../../domain/equipment-schedule.md) CV1–CV8. 날짜별 교대(WC29, D1)와 쉬는 날(WC3)은 이미 사유를 받는다.

## 결정

| # | 결정 | 누가 |
|---|---|---|
| 1 | 작업자의 근무표 판과 설비 달력 판마다 선택 사유 `reason`을 둔다. 앞뒤 공백을 떼고, 비면 없음, 200자까지. 날짜별 교대와 쉬는 날의 사유와 같은 규칙이다 | 사용자 사전 위임(2026-10-18) |
| 2 | 받는 곳: 작업자 주간 교대 저장, 팀 근무표 복사(모든 대상에 같은 사유), 설비 달력 저장, 설비 달력 지우기(`DELETE …/calendar?reason=`) | 사용자 사전 위임(2026-10-18) |
| 3 | 저장할 때마다 보낸 사유로 바뀐다. 같은 날짜로 다시 저장하면 교대처럼 사유도 새로 보낸 것으로 바뀌고, 빼면 없어진다 | 사용자 사전 위임(2026-10-18) |
| 4 | 응답: 판 목록과 판 조회에 `reason`, `updatedBy`, `updatedAt`. 누가 언제 그 판을 마지막으로 저장했는지도 보인다 | 사용자 사전 위임(2026-10-18) |
| 5 | 화면: Starts on·Applies from 옆에 **Note**(접근 이름 `Shift version note`, `Calendar version note`). 판 줄 끝에 ` · 사유`. Edit은 사유도 불러온다. 팀 근무표 복사 화면에는 넣지 않는다 | 사용자 사전 위임(2026-10-18) |
| 6 | 화면 이름은 Note다. 설비 화면 정지 폼의 Reason과 이름이 겹치지 않게 했다. API 필드는 날짜별 교대와 같은 `reason`이다 | 사용자 사전 위임(2026-10-18) |
| 7 | 새 마이그레이션 V95: `worker_schedule.reason`, `equipment_schedule.reason`(varchar(200), NULL 허용). 지난 판에는 사유가 없다 | 사용자 사전 위임(2026-10-18) |

## 수용 기준 (2026-10-18)

- [x] 사유 규칙: 선택, 200자, 저장마다 바뀜(결정 1·3)
- [x] 받는 곳과 응답: 결정 2·4
- [x] 화면: 결정 5·6
- [x] 마이그레이션: V95, 채워 넣을 값 없음

## 결정하지 않은 것

- 사유를 필수로 할지(지금은 선택)
- 판의 저장 이력(한 판을 여러 번 고친 기록)을 따로 남길지. 지금은 마지막 저장만 남는다. [ADR-024](ADR-024-version-save-history.md)에서 남기게 했다(2026-10-19)

## 결과

- 좋은 점: 근무표나 설비 교대가 왜 그날부터 바뀌는지 판 목록에서 바로 보인다.
- 위험: V95가 커밋 전 마이그레이션에 하나 더 붙는다(V88–V95). 열만 더하므로 기존 행은 그대로다.
