# ADR-037: 워크플로 안내 보기(Guided views)의 장 저장

작성일: 2026-11-20

## 상태

**Accepted (2026-11-20, 2026-10-24 사용자 위임으로 권장안 A).** 구현(2026-11-20): 서버 V136(`GuidedViewIntegrationTest`), 화면은 보기 도구의 VIEWS(`guided-views.spec.ts`). [archify 대조표](../../editor/archify-parity.md)의 마지막 "없음" 줄이고, [월간 계획](../../status/MONTH-PLAN-2026-11-16.md)이 "장 목록을 저장할 곳을 ADR로 먼저 정한다"고 적어 둔 결정이다.

## 배경

- archify의 안내 보기는 다이어그램을 몇 개의 장(view)으로 나눠 보여 준다. 장마다 id, 이름(1–48자), 강조할 노드 목록(1개 이상), 메모(140자까지)가 있고, 한 다이어그램에 장은 5개까지다. 읽는 사람은 장을 넘기거나 재생한다. 재생은 장마다 3.2초이고, 장 안에서는 노드를 하나씩 따라간다. `#view=<id>&beat=<노드>` 링크로 그 장의 그 순간을 남에게 보낸다.
- archify는 장을 다이어그램 파일 안에 적는다. 파일을 만드는 사람이 장도 쓴다. FlowMat의 워크플로는 서버에 있고 여럿이 고치며, 발행하면 그때의 모습이 판(revision)으로 남는다([workflow-revision](../../domain/workflow-revision.md)). 장을 어디에 두느냐에 따라 누가 고치는지, 링크가 언제까지 맞는지, 발행 판에 장이 따라가는지가 달라진다.
- 장은 업무 자료가 아니다. 재고·생산·연동은 장을 읽지 않는다. 장이 가리키는 것은 공정이다.

## 선택지

| | A. 새 표 `workflow_guided_view` | B. 편집 문서의 열 하나 | C. 브라우저에만 |
|---|---|---|---|
| 저장 | 장마다 한 줄. workflow 모듈이 가진다 | `workflow_editor_document`에 jsonb 열 | `localStorage` |
| 고치기 | 장 하나씩, 장마다 version | 편집 문서 전체를 저장할 때 함께. 문서 version이 오른다 | 그 브라우저만 |
| 함께 고칠 때 | 다른 장, 도형, 공정을 고치는 사람과 부딪히지 않는다 | 도형을 고치던 사람과 같은 version을 다툰다 | 해당 없음 |
| 링크를 받은 사람 | 같은 장을 본다 | 같은 장을 본다 | 장이 없다 |
| 발행 판 | 발행할 때 스냅숏에 넣는다 | 편집 문서가 이미 스냅숏에 들어간다 | 들어가지 않는다 |
| 비용 | 마이그레이션, API 다섯 개, 스냅숏 필드 하나 | 마이그레이션 하나. 대신 도형 편집기(flowmat-editor)의 문서 계약에 도형과 무관한 것이 섞인다 | 서버 변경 없음 |

C는 archify 안내 보기의 쓸모(장을 링크로 건네기)를 잃는다. B는 가장 싸지만, 장 이름 하나를 고쳐도 편집 문서 전체의 version이 올라 도형을 고치던 사람의 저장이 충돌하고, 별도 저장소로 나간 편집기 패키지의 문서 형식에 FlowMat만의 것이 들어간다. **A를 고른다.**

## 결정

1. **저장.** `workflow_guided_view` 표(V136)를 workflow 모듈이 가진다. 열은 `guided_view_id`, `workflow_id`, `project_id`, `sort_order`, `label`(1–48자), `note`(140자까지, 비우면 null), `focus_process_ids`(jsonb 배열), `version`, 만든·고친 사람과 시각이다. 지운 장은 행을 지운다. 장은 업무 기록이 아니어서 이력을 남기지 않는다.
2. **한도.** 워크플로마다 장 8개까지. archify는 5개이지만 한 장짜리 설명 그림 기준이고, FlowMat 워크플로는 공정이 수십 개다(성능 기준선의 시뮬레이션 워크플로는 60개). 장 하나의 공정은 1–30개이고, 같은 워크플로의 지워지지 않은 공정이어야 하며 겹치지 않는다. 순서는 사람이 정한 그대로다(장 안의 공정 순서가 재생 순서다).
3. **API.** 주석(annotation)처럼 워크플로 아래에 둔다. `GET /workflows/{workflowId}/guided-views`(읽기 권한), `POST …/guided-views`, `PUT …/guided-views/{id}`(version 필수, 다르면 409, 없으면 400), `DELETE …/guided-views/{id}`, `PUT …/guided-views/order`(모든 장의 id를 새 순서로 한 번씩). 쓰기는 공정을 고치는 것과 같은 워크플로 쓰기 권한이고, 워크플로 행을 잠근 뒤 장 수·순서·version을 확인한다. 이름과 메모의 길이는 사람이 세는 글자 수(코드 포인트)로 센다.
4. **공정이 지워지면.** 장의 공정 목록은 고치지 않고, 읽을 때 지워진 공정을 뺀다(archify도 없는 노드를 읽을 때 뺀다). 공정 삭제가 장을 알 필요가 없다. 남은 공정이 없는 장은 목록에 "공정 없음"으로 남고 재생은 건너뛴다. 장을 다시 저장하면 그때 목록이 정리된다.
5. **발행.** 발행할 때 그때의 장을 revision 스냅숏의 `guidedViews`에 넣는다(비어 있으면 빼는 추가 필드라 스냅숏 schemaVersion은 그대로다). 발행 판을 캔버스에서 읽는 화면이 생기면 그 판의 장을 읽기 전용으로 보인다(2026-11-20에는 그런 화면이 없어 스냅숏에 남겨 두기만 한다). 이전에 발행한 판에는 장이 없다.
6. **읽기 화면.** 보기 도구에 VIEWS 단추를 두고, 다른 읽기 패널처럼 한 번에 하나만 연다. 장 목록, 이전·다음, 재생·멈춤, 장 이름과 메모를 보인다. 장을 고르면 그 공정들과 그 사이 연결을 강하게, 나머지를 흐리게 보이고(렌즈·도달과 같은 강조) 카메라가 그 공정들에 맞춘다. 재생은 장 안의 공정을 하나씩 1.2초씩 짚고(archify는 장마다 3.2초이지만 FlowMat의 장은 공정이 더 많다), 장이 끝나면 다음 장으로, 마지막 장 뒤에 멈춘다. 공정을 짚을 때 카메라는 움직이지 않는다. Still이거나 시스템이 동작 줄이기를 요청하면 카메라는 움직임 없이 옮긴다. 주소는 `#view=<id>`, 장 안의 순간은 `&beat=<processId>`다(읽기 hash의 다른 항목과 같은 규칙).
7. **만들기 화면.** 쓰기 권한이 있으면 같은 패널에서 "선택한 공정으로 장 만들기", 이름·메모 고치기, 위·아래로 옮기기, 지우기를 한다. 발행 판을 읽을 때는 이 단추들이 없다.
8. **모듈 목록.** 표는 workflow 모듈의 엔티티(`GuidedView`)가 매핑하므로 `ModuleCatalogDataTest`가 workflow의 소유로 본다. `modules.yml`의 workflow 책임 설명에 안내 보기를 더한다. 다른 모듈은 이 표를 읽지 않는다.

## 결정하지 않은 것

- 장을 내보내기(공유 카드·WebM)에 쓰기. 장을 따라 녹화하는 WebM은 장이 들어간 뒤에 따로 본다.
- 장을 다른 워크플로로 복사하기, 템플릿에 넣기.
- 장 이름의 다국어. 화면 문구 다국어(대조표의 "가져오지 않음" 줄)와 같이 정한다.

## 결과

- 좋은 점: 장을 고치는 일이 도형·공정 편집과 부딪히지 않는다. 링크를 받은 사람이 같은 장을 본다. 발행 판은 발행 때의 장을 그대로 보인다.
- 비용: 표 하나와 API 다섯 개, 스냅숏 필드 하나, 프런트의 패널 하나가 는다. 공정이 지워진 장의 목록은 다음 저장까지 지운 id를 품는다(읽을 때 빼므로 화면에는 보이지 않는다).

## 검증

구현할 때 아래가 테스트로 남는다.

- 통합 테스트(실제 Postgres): 만들기·고치기·순서·지우기, 읽기 권한만 있으면 쓰기 403, 9번째 장 400, 다른 워크플로나 지운 공정 400, 같은 공정 두 번 400, version이 다르면 409, 공정을 지운 뒤 읽으면 빠짐, 발행 스냅숏에 장이 들어가고 그 뒤에 장을 고쳐도 판은 그대로.
- 브라우저 테스트: 선택으로 장 만들기 → 재생 → `#view=` 링크로 열기 → 발행 판에서 읽기 전용으로 읽기.
