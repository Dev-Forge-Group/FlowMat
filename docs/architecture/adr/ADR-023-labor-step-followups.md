# ADR-023: 단계 작업자 시간의 보정과 공정별 합계

작성일: 2026-10-19

## 상태

**Accepted (2026-10-19). 로컬 구현 2fb(2026-10-19, 커밋 전, V100).** [ADR-021](ADR-021-labor-step.md)이 남긴 두 가지("보정 줄에서 단계를 고르는 것", "단계의 작업자 시간을 작업지시 대비에 단계별로 나눠 보이는 것")를 골랐다(사용자 지시 "어떤기능이던 지금 구현된 기능과 연관된것 부터 처리해", 2026-10-18). 세부는 사용자 사전 위임(2026-10-18, "구현 중 새 설계 선택 | 권장안으로 진행")에 따라 리드가 고른 권장안이다.

근거: [ADR-020](ADR-020-labor-correction.md)(끝난 실행의 작업자 시간 보정), [ADR-021](ADR-021-labor-step.md)(생산 단계의 작업자 시간), [작업자 달력](../../domain/worker-calendar.md) LB6, LB9–LB18.

## 결정

| # | 결정 | 누가 |
|---|---|---|
| 1 | 보정 줄 `add_labor`도 `stepId`를 줄 수 있다. 실행 기록(LB13)과 같은 검사이고, 빼면 실행 전체다. 승인하면 만든 기록이 그 단계를 가리킨다 | 사용자 사전 위임(2026-10-18) |
| 2 | 화면의 보정 요청도 시작한 단계를 고를 수 있고, 고르면 분은 그 단계의 시간 × 몫에서 시작한다(LB16과 같다) | 사용자 사전 위임(2026-10-18) |
| 3 | 작업지시 대비(LB6)에 공정마다 실제 분을 더한다. 실행이 달라도 같은 공정(노드)이면 더하고, 공정 순서대로 보인다. 단계를 고르지 않은 분은 `wholeRunMinutes`다. 계획을 공정별로 나누지는 않는다(계획은 사람별 몫뿐이다) | 사용자 사전 위임(2026-10-18) |
| 4 | 새 마이그레이션 V100: `production_run_correction_line.labor_step_id`(NULL 허용, 외래 키 없음) | 사용자 사전 위임(2026-10-18) |

## 수용 기준 (2026-10-19)

- [x] 보정 줄의 단계: 결정 1·2(LB17)
- [x] 공정별 합계: 결정 3(LB18)
- [x] 마이그레이션: V100, 채울 값 없음

## 결정하지 않은 것

- 공정별 계획 인력 시간(지금 계획은 사람별 몫뿐이다)

## 결과

- 좋은 점: 보정으로 더한 시간도 어느 공정의 것인지 남고, 작업지시에서 공정마다 실제로 든 작업자 시간이 보인다.
- 위험: V100이 커밋 전 마이그레이션(V95–V100)에 붙는다. 열 하나만 더한다.
